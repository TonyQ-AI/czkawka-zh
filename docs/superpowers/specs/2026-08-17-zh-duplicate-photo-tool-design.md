# 中文重复照片筛查工具（基于 czkawka 定制）— 设计文档

- 日期：2026-08-17
- 状态：已获用户批准并完成实现（按 spec-kit 流程，见 `specs/001-duplicate-photo-tool/`；实现细节以该处为准）
- 项目位置：`项目根目录`（fork 自 qarmin/czkawka 最新版）

## 1. 背景与目标

用户在电脑中存有大量照片，其中存在重复与相似版本（文件名、大小可能不同）。需要一个**中文界面的图形工具**来快速筛查重复照片，并具备"自动建议保留最清晰一张"的能力。

### 已确认的需求要点（来自用户澄清）

| 要点 | 结论 |
|---|---|
| 重复定义 | 两种情况都要：完全相同的副本 + 内容相似（不同分辨率/压缩/格式/水印的版本） |
| 规模 | 照片数量不确定，越多越好（算法需对规模不敏感，避免 O(n²) 全量两两比对） |
| 形态 | 独立 GUI 工具，中文界面，不与用户其他项目打通 |
| 基座 | 基于开源 czkawka（qarmin/czkawka，32.7k stars）fork 定制，增量开发 |
| 前端 | Krokiet（Slint GUI，官方主线） |
| 清晰度判定 | 分辨率（width×height）优先，文件大小辅助；EXIF 对焦信息不采用 |
| 处理流程 | 每组自动按清晰度排序 + 自动标记"建议保留" + 手动可覆盖 + 确认后处理 |
| 默认动作 | 移到回收站（可恢复）；永久删除需二次确认 |
| 许可证认知 | 核心库 MIT；Krokiet GUI 为 GPL-3.0。用户自用或公开源码均合规，已了解 |

### 关键既有数据结构（已验证）

`czkawka_core/src/tools/similar_images/mod.rs:34` 的 `ImagesEntry` 已包含：

```rust
pub struct ImagesEntry {
    pub path: PathBuf,
    pub size: u64,
    pub width: u32,
    pub height: u32,
    pub modified_date: u64,
    pub hashes: Vec<ImHash>,
    pub difference: u32,
}
```

**结论：清晰度评分所需数据（分辨率、大小）在哈希阶段已采集，评分无需重新解码图片，性能零损耗。**

`similar_vectors: Vec<Vec<ImagesEntry>>` 是相似分组输出（每个元素是一个相似组），参考条目对 `similar_referenced_vectors: Vec<(ImagesEntry, Vec<ImagesEntry>)>` 同样可用。

## 3. 功能设计

### 3.1 清晰度评分（czkawka_core）

**新增文件**：`czkawka_core/src/tools/similar_images/similarity_ranking.rs`

**评分规则**（纯函数，不修改现有结构与状态）：

```
clarity_score(entry) = (width * height) * 1000 + (size / 1024)
```

- 第一排序键：**总像素数**（width×height）——分辨率越高越清晰
- 第二排序键：**文件大小**（KB）——同分辨率下体积大者优
- 输出：`rank_by_clarity(entries: &mut [ImagesEntry])` 原地按得分降序排序，返回建议保留索引（默认索引 0）

**边界处理**：
- width 或 height 为 0（哈希失败/无法解码的图片）：得分视为 0，排在最后（仍参与分组，但不会被建议保留）
- 完全相同时：按路径字典序稳定排序（确定性）

**单元测试**（`#[cfg(test)]` 内联）：
1. 同分辨率不同大小 → 大者优先
2. 不同分辨率 → 像素多者优先（即使体积小）
3. 0 尺寸条目 → 排最后
4. 稳定排序 → 完全相同条目顺序可预测

### 3.2 相似图片结果展示（krokiet）

在相似图片（Similar Images）结果页：

1. **分组内排序**：结果加载后，对每个相似组内的成员调用 `rank_by_clarity`，按清晰度从高到低显示
2. **建议保留标记**：每组默认在得分最高的一行显示"⭐ 建议保留"
3. **手动覆盖**：每行提供勾选框/选择手柄，用户点选后，⭐ 标记移到被选行；允许取消选择（此时回落到"无建议仅排序"状态）
4. **全组选择辅助**：组头提供"保留最清晰"快捷按钮（一键采用自动建议）

### 3.3 批量处理操作（krokiet）

结果页底部操作区新增按钮：

| 按钮 | 行为 | 默认可见 |
|---|---|---|
| 移到回收站 | 未保留项进系统回收站（可恢复） | ✅ 默认动作 |
| 移到指定文件夹 | 未保留项从原位置移动到用户选择的文件夹（原位置不再保留文件） | ✅ 可选项 |
| 永久删除 | 需勾选"我已确认"，二次确认后执行 | ⚠️ 仅显式勾选后可用 |

**执行前后一致性**：
- 操作前收集所有未保留项的路径
- 逐项执行，单项失败记录到日志并在界面提示（不中断整体）
- 操作完成后从结果列表移除已处理项，保留项留在列表并标记"已处理"

## 4. 错误处理

| 场景 | 处理 |
|---|---|
| 图片解码失败（width=0） | 排末位，不误标建议保留 |
| 文件被占用/删除导致处理失败 | 记录日志，界面提示，继续处理其余项 |
| 目标文件夹不存在 | 自动创建；创建失败则提示并中止该操作项 |
| 回收站不可用（极端环境） | 回退为"移到指定文件夹"模式并提示 |
| 用户未选择任何保留项 | 禁用批量操作按钮，提示先选择保留项 |
