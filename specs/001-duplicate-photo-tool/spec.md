# Feature Specification: 中文重复照片筛查工具

**Feature Branch**: `001-duplicate-photo-tool`

**Created**: 2026-08-17

**Status**: Draft

**Input**: User description: "基于 czkawka 定制一款中文界面的重复/相似照片筛查工具：找出完全相同的副本与内容相似的照片版本，自动建议每组保留最清晰的一张，用户可手动覆盖，确认后统一处理（默认回收站、可永久删除需二次确认）"

## User Scenarios & Testing

### User Story 1 - 扫描并找出重复与相似照片 (Priority: P1)

用户选择照片所在文件夹/磁盘后启动扫描，工具在合理时间内找出所有重复组——既包括**完全相同**的副本（文件名、大小可能不同），也包括**内容相似**的版本（分辨率不同、压缩过、格式不同、加水印等）。结果按组展示，用户一眼可以看到一组照片是同一个画面。

**Why this priority**: 这是工具的核心价值——没有这一步，后续所有功能无从谈起。独立可用即为本工具的最小可行产品。

**Independent Test**: 向包含已知重复照片的测试目录运行扫描，检查结果是否按重复组正确分组，且包含完全重复组与相似组。

**Acceptance Scenarios**:

1. **Given** 照片文件夹含两张像素完全一致的图片（文件名、大小不同），**When** 用户运行扫描，**Then** 两张图片出现在同一个重复组中
2. **Given** 照片文件夹含同一画面的不同分辨率/压缩版本，**When** 用户运行扫描，**Then** 这些版本出现在同一个相似组中
3. **Given** 照片文件夹含完全不同的图片，**When** 用户运行扫描，**Then** 它们不会出现在任何重复组中
4. **Given** 照片数量达到数万张，**When** 用户运行扫描，**Then** 扫描在可接受的等待时间内完成且不出现内存耗尽（算法对规模不敏感）

---

### User Story 2 - 自动建议保留最清晰的一张 (Priority: P1)

每个重复组内，工具自动按清晰度从高到低排序，并标记"⭐ 建议保留"最清晰的一张（分辨率优先、同分辨率看文件大小），让用户不需要逐张对比细节就能知道该留哪张。

**Why this priority**: "自动保留最清晰"是用户明确的核心诉求，是减少手动判断负担的关键。

**Independent Test**: 对包含同画面不同分辨率/质量的测试组，检查建议保留标记是否落在最高分辨率（像素数最多）的文件上。

**Acceptance Scenarios**:

1. **Given** 一个重复组内包含 3 个版本（1000×800、800×600、500×400），**When** 扫描完成，**Then** "建议保留"标记落在 1000×800 的文件上
2. **Given** 组内两个文件分辨率相同但体积不同，**When** 扫描完成，**Then** "建议保留"标记落在体积较大的文件上
3. **Given** 组内某文件解码失败（无有效尺寸信息），**When** 扫描完成，**Then** 该文件排在最末且不会被建议保留

---

### User Story 3 - 手动覆盖保留选择 (Priority: P2)

用户不同意自动建议时，可以在组内点选自己真正想保留的文件（例如更喜欢低分辨率但带滤镜的版本），工具尊重用户选择更新保留标记。

**Why this priority**: 自动建议不能替代人的主观偏好，手动覆盖确保用户对结果有最终控制权，且实现成本低。

**Independent Test**: 用户点击组内另一行，检查"建议保留"标记是否移动到该行。

**Acceptance Scenarios**:

1. **Given** 组内已标记建议保留某文件，**When** 用户点击选择同组内的另一文件，**Then** 建议保留标记移动到用户选择的文件
2. **Given** 用户已手动选择保留项，**When** 触发批量操作，**Then** 系统仅处理未保留项，用户选择项绝不被处理

---

### User Story 4 - 确认后统一处理（默认回收站） (Priority: P2)

用户确认保留选择后，对每组未保留的项执行批量处理。默认动作是**移到系统回收站**（可恢复），也可选择移到指定文件夹；永久删除需显式勾选"我已确认"并二次确认。所有操作在执行前展示将要处理的文件清单，无法恢复的操作（永久删除）有额外防护。

**Why this priority**: 这是完成闭环的关键一步——只标记不处理无法帮用户释放空间。但安全性优先，所以默认走可恢复路径。

**Independent Test**: 对测试目录执行"移到回收站"，检查文件进入回收站且可从回收站恢复；再测试永久删除路径需要二次确认。

**Acceptance Scenarios**:

1. **Given** 用户已为各组选定保留项，**When** 用户点击"移到回收站"，**Then** 所有未保留项进入系统回收站，保留项保留在原位，原重复组从结果列表消失
2. **Given** 用户点击"永久删除"而未勾选确认，**When** 系统收到操作请求，**Then** 永久删除按钮不可用/被阻止
3. **Given** 用户勾选"我已确认"后点击"永久删除"，**When** 系统弹出二次确认对话框，**Then** 用户确认后文件被删除，取消则不执行任何操作
4. **Given** 批量处理中有个别文件失败（被占用等），**When** 处理结束，**Then** 失败的项被记录并在界面提示，其余项正常处理

---

### Edge Cases

- 照片文件夹中包含不是图片的文件（视频、文档、隐藏文件）→ 不纳入图片扫描（沿用图片扩展名过滤）
- 空文件夹/无图片的文件夹 → 扫描正常完成，结果为空，无报错
- 权限不足的文件夹/文件 → 跳过并警告，不中断整体扫描
- 大量重复组同时存在 → 结果可滚动查看，操作按已选组批量执行
- 图片被其他程序占用 → 处理失败时记录并提示，不中断其他项
- 用户未选择任何保留项 → 批量操作按钮禁用并提示先确认保留项
- 组内只有一张照片（并非重复）→ 不进入任何重复组，不受批量操作影响
- 扫描过程中用户主动停止 → 已扫描部分保留，可查看部分结果

## Requirements

### Functional Requirements

- **FR-001**: 系统必须支持选择磁盘/文件夹作为扫描范围，并递归扫描子目录
- **FR-002**: 系统必须识别"完全相同"的重复照片（内容完全一致，忽略文件名/大小差异）
- **FR-003**: 系统必须识别"内容相似"的照片版本（不同分辨率、压缩、格式、水印）
- **FR-004**: 系统必须确保扫描算法对照片规模不敏感（避免全量两两比较，大库不退化）
- **FR-005**: 系统必须为每个重复/相似组内的照片计算清晰度排名，规则为：总像素数（分辨率）优先，同分辨率时文件大小次之
- **FR-006**: 系统必须在每个组内自动标记"建议保留"清晰度排名第一的照片
- **FR-007**: 系统必须允许用户手动点选组内任意照片作为保留项，覆盖自动建议
- **FR-008**: 系统必须提供批量处理操作：移到系统回收站（默认）、移到用户指定文件夹、永久删除
- **FR-009**: 系统必须在执行批量处理前展示涉及文件清单；永久删除必须要求显式勾选确认并二次确认
- **FR-010**: 系统必须保证删除/移动操作只作用于未被保留的文件，用户保留项绝不被处理
- **FR-011**: 系统必须在处理失败时记录失败项并在界面提示，不中断其余处理
- **FR-012**: 系统必须提供中文界面，且新增界面对话可在中文与英文间切换
- **FR-013**: 系统必须将处理结果反馈给用户（成功数量、失败数量、去重后释放的大致空间）

### Key Entities

- **照片文件**: 被扫描的图片文件，包含路径、分辨率（宽×高）、文件大小、修改时间等属性
- **重复/相似组**: 由内容相同或相似的若干照片文件组成的集合，组内成员共享同一画面
- **保留项**: 用户（或系统建议）决定保留的照片，组内其他成员为待处理候选
- **处理动作**: 应用于待处理候选的批量操作（回收站/移文件夹/永久删除）
- **扫描任务**: 一次完整扫描的状态与结果（扫描路径、参数、进度、分组结果）

## Success Criteria

### Measurable Outcomes

- **SC-001**: 用户从选择文件夹到看到分组结果无需任何手工比对，全程只需等待扫描完成
- **SC-002**: 每个重复组在结果中自动带有清晰度排序和"建议保留"标记，无需用户逐张放大对比
- **SC-003**: 用户完成"扫描→确认保留→批量回收站"全流程不超过 5 个主要操作
- **SC-004**: 对含重复照片的测试目录，重复组识别准确率 100%（测试样本内无漏报/误报）
- **SC-005**: 系统的误删风险为零：保留项在任何操作下都不会被动到，永久删除路径无法在没有双重确认的情况下执行
- **SC-006**: 扫描性能不随照片数量急剧退化（万张以内单机可完成，十万级可分批或耗时在可接受数量级）
- **SC-007**: 所有界面文案在中文模式下完整显示，无缺漏英文残留

## Assumptions

- 目标平台为 Windows（本机），界面为桌面图形程序
- 照片主要格式为常见图片格式（JPG/PNG/HEIC/WebP/RAW 等，以 czkawka 支持范围为准）
- 用户自用场景：对许可证（GPL-3.0 的 GUI 部分）已了解，自用或公开源码均合规
- 检测能力复用成熟开源实现（czkawka 的哈希与感知哈希分组），本功能不重造算法
- 扫描与处理均为本地操作，不涉及云服务、账号体系或网络传输
- 视频、音频、文档等其他文件类型的去重不在本次范围（czkawka 已有对应工具，本次不改动）
- 手机照片通常附带的 EXIF 对焦/锐度信息不作为清晰度判据（可靠性不足，已确认）
